# Attendance + Summary Redesign (Nockacademy) — SPEC DRAFT

สถานะ: ร่างจากบทสนทนา 2026-11-26 · ยังไม่แตะโค้ด · รอเจ้าของ (Dai) รีวิว
ขอบเขต: เฉพาะแบรนด์ที่ใช้ Summary (Nockacademy) · Liclass ซ่อน Summary อยู่แล้ว (`brandUsesSummary`)

## 1. สถานะคาบ

เหลือ 4: **Upcoming · Live · Past · Cancelled**
- ตัด `needs_attendance` ("เช็คชื่อ") และ `needs_summary` ("สรุป") ออกจาก `workState` ใน `src/domain/rules/scheduling.ts`
- ตัดแนวคิด `overdue` ของคาบที่จบแล้ว
- ผลกระทบที่ต้องไล่แก้: ชิปสถานะในปฏิทิน/ตาราง · Teacher Health (สรุปค้าง, ยังไม่เช็คชื่อ, สรุปตรงเวลา) · Dashboard/Reports ที่นับงานค้าง · เมนู /summaries · i18n

## 2. เช็คชื่อ

- ทุกคนถือว่า **มา** โดยปริยาย ไม่มีปุ่ม "บันทึกเช็คชื่อ" และไม่มีข้อความ "ยังไม่ได้บันทึก"
- ครูแตะเฉพาะคนที่ **ลา / ขาด** (และ Partial / ย้าย ผ่านเมนู ⋯)
- **หักโควตาเมื่อคาบเป็น Past** ยกเว้นคนที่ถูกตั้งลา/ขาด/ย้ายไว้

## 3. ขั้นยืนยัน (เหตุผล: ทุกอย่างผูก Session · Course · Invoice · ต้นทุนครู)

| การกระทำ | ยืนยัน? |
|---|---|
| มา (ค่าเริ่มต้น) | ไม่ต้อง |
| ลา / ขาด | **ต้อง** |
| ย้ายคาบ (ครั้งเดียว / ถาวร) | **ต้อง** |
| เวลาเรียน Partial (คาบนี้ / ทุกคาบ) | **ต้อง** |
| กลับจากลาเป็นมา | **ต้อง** (ย้อนต้นทุนกลับ) |

เวลาเรียน Partial (เมนู "เวลาเรียนของ…"): ทำได้ทั้ง **เฉพาะคาบนี้** และ **ทุกคาบ** (เจ้าของยืนยัน 2026-11-26 ว่าต้องมีทางเลือกทุกคาบ) — หน้ายืนยันของแบบทุกคาบต้องแสดงผลรวมทุกคาบที่ได้รับผลกระทบ

หน้ายืนยันต้องสรุปผลกระทบก่อนมีผล:
- โควตาคอร์ส: หัก/ไม่หัก · เหลือกี่คาบ · ลาในสิทธิ์/เกินสิทธิ์
- ต้องมีคาบชดเชย/ย้ายหรือไม่
- Invoice / เครดิตของนักเรียน
- ค่าสอนครู / ห้อง

รูปแบบ: ปุ่มยืนยันอยู่แถบล่างของแผง (ตาม Panel structure) · ทางเลือกเชิงลบอยู่ใน ⋯ · ย้ายคาบและเวลาเรียนมี flow อยู่แล้ว (เมนู ⋯ ของนักเรียนใน SessionSheet) → เติมส่วน "ผลกระทบ" เข้า flow เดิม ส่วน "ลา" เปลี่ยนจากกดทันทีเป็นผ่านหน้ายืนยัน

## 4. Summary แยก 2 เรื่อง (ทั้งคู่ optional ไม่มีเส้นตาย ไม่มีงานค้าง)

| | Student Summary | Lesson Summary |
|---|---|---|
| ผู้อ่าน | ผู้ปกครอง | ครู (สอนแทน/รับช่วง) |
| จุดประสงค์ | รายงานผลเด็ก | ความทรงจำของคลาส/นักเรียน: สอนอะไรไปแล้ว |
| เขียน | ตอนไหนก็ได้ หรือไม่เขียน | ตอนไหนก็ได้ หรือไม่เขียน |
| อนุมัติ/ส่ง | flow เดิม (maker–checker, ส่งผู้ปกครอง) เมื่อครูเลือกเขียน | ไม่ต้อง (บันทึกภายใน) |

**เขียนได้ทุกคาบ (เจ้าของ 2026-11-26):** ไม่ผูกกับสถานะคาบ — เขียน/แก้ได้ทั้ง Upcoming, Live และ Past (รวมคาบเก่าย้อนหลัง) ไม่มีช่วงเวลาที่ถูกล็อกเพราะ "พ้นกำหนด"

UI หลักของ Lesson Summary = ไทม์ไลน์ "ประวัติการสอน" ในแผงนักเรียนและแผงคลาส (ไม่ใช่รายการงานค้าง)

## 5. ยังไม่ได้ตัดสิน (ต้องถามเจ้าของ)

1. Lesson Summary เขียนระดับคาบ (ทั้งคลาส, ปรับรายคนได้) หรือรายคน — แนะนำระดับคาบ
2. Lesson Summary ต้องอนุมัติไหม — แนะนำไม่ต้อง
3. คะแนนความเข้าใจ 1–5 (`level`) อยู่ฝั่งไหน — แนะนำแยกจากข้อความ ให้ครูให้คะแนนได้โดยไม่ต้องเขียน
4. Course Summary ดึงข้อมูลจากไหนเมื่อครูข้าม Student Summary
5. ครูเลือก "ไม่เขียน Student Summary" ต้องระบุเหตุผลไหม / ผู้จัดการดูสถิติการข้ามได้ไหม
6. Teacher Health จะวัดอะไรแทน "สรุปค้าง/ตรงเวลา"
