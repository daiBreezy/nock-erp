# ตาราง B — Policy Definition

> เติมหลังจากทำ A เสร็จ — เพราะ A จะบอกว่าจริงๆ ใช้ policy กี่ตัว
> **แถวไหนไม่มีใครใน A ชี้มา = ลบทิ้ง** (policy ที่ไม่มีคนใช้ = ขยะ)

| คอลัมน์ | คำอธิบาย |
|---|---|
| `policy_id` | ATT-001 / OT-001 / … |
| `name` | ชื่อสั้น |
| `applies_to` | ใครใช้บ้าง (ดึงจาก A) |
| **`condition`** ⭐ | **เงื่อนไข** — "เมื่อไหร่ที่กฎนี้ทำงาน" |
| **`calculation`** ⭐ | **สูตร** — เขียนเป็นเลขจริง ไม่ใช่คำบรรยาย |
| **`outcome`** ⭐ | **ผลลัพธ์** — บวก/หักเงินเท่าไหร่ ลงช่องไหน |
| `example` | เคสจริง 1 เคสพร้อมตัวเลข |
| `status` | `confirmed` / `assumed` / `unknown` |
| `source` | ใครบอก + วันที่ |

**`condition` + `calculation` + `outcome` = 3 ช่องนี้คือหัวใจ** ตารางเก่าไม่มีสักช่อง

# ตาราง E — Decision Log

> **นี่คือตัวที่เปลี่ยน "ตัดสินใจใหม่ทุกเดือน" → "ยืนยันว่าเหมือนเดิม"**
> เคสตัดสินใจ (A-type) ส่วนใหญ่คือเคสเดิมที่วนกลับมา ถ้าจดไว้ ครั้งหน้าแค่พยักหน้า

| คอลัมน์ | คำอธิบาย |
|---|---|
| `month` | 2026-07 |
| `emp_id` | ใคร |
| `case` | เจอสถานการณ์อะไร |
| `decision` | ตัดสินใจว่ายังไง |
| `amount_effect` | กระทบเงินเท่าไหร่ |
| `decided_by` | ใครตัดสิน |
| `repeat` | เคยเจอเคสนี้มาก่อนไหม (Y/N) |

**วิธีใช้:** เดือนถัดไปเปิดดูก่อนเริ่มคำนวณ — เจอ `repeat=Y` แปลว่าไม่ต้องคิดใหม่
**ผลข้างเคียงที่สำคัญ:** ป้องกันการตัดสินไม่เหมือนเดือนก่อน = ไม่แฟร์กับพนักงาน

# วิธีใช้พรุ่งนี้

1. เปิด **ตาราง A** เปล่า
2. ให้ Admin ไล่ชื่อทีละคน ตอบ 6 ช่อง 🔴 (คนละ ~30 วินาที)
3. ได้ยินคำว่า *"คนนี้พิเศษ..."* → ลง `special_note` + `calc_mode = manual`
4. **Admin ลังเล/คิดนาน → `calc_mode = manual`** แม้เขาจะตอบได้ในที่สุด
5. เจอ `?` → เขียนลง **ตาราง D** ทันที ระบุว่าต้องถามใคร
6. จบแล้วนับ: **manual กี่คน**

ตัวเลข manual นั่นแหละคือคำตอบว่าต้องสร้างอะไร — และเราจะรู้ในวันเดียว

**สิ่งที่ยังไม่ต้องทำพรุ่งนี้:** ตาราง B (รอ A ก่อน) · ห้ามถาม KMD/ธนาคาร · ห้ามคุยเรื่องระบบหรือหน้าจอ
