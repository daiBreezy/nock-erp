## 🔑 ข้อค้นพบสำคัญ (ยืนยันแล้วจาก Doc)

1. **1 Vendor → หลาย WHT line** = ที่มาของ "32 ใบ/เดือน" จาก ~15 เจ้า
   - NAS Srinakarin = 4 ใบ (ค่าเช่า+ภาษีที่ดิน 5% · ค่าบริการ 3% · ค่าบริการอุปกรณ์ 3%)
   - ⇒ WHT ต้องเก็บเป็น **line ต่อหมวด** ไม่ใช่ต่อ vendor

2. **ประเภท → แบบยื่น + อัตรา = deterministic** (สิ่งที่ Admin "จำเอา")
   - บริษัท/หจก. → ภงด.53 · บุคคล → ภงด.3
   - ค่าเช่า 5% · ค่าบริการ 3% · ค่าโฆษณา 2%

3. **e-WHT มีใช้แล้วบางเจ้า** (AIS/True/Fujifilm) → พิสูจน์ว่าทำได้ แค่ยังไม่ครบ

4. **VAT 7% ปนอยู่ในบิลค่าบริการ** (ชาร์จ+vat 7%) → ยืนยันว่ามี taxable component จริง

| คำถาม | คำตอบ KMD |
|---|---|
| **VAT** | ✅ **บริษัทจด VAT แล้ว · ภ.พ.20 = 0-2055-57003-96-5** |
| VAT ผูกกับอะไร (สาขา/สินค้า/สาย) | ❌ **ไม่ทราบ** — ยังค้าง |
| รายได้ตัวไหน taxable | ❌ Liclass "ยังไม่ได้ผูกกับอะไร" · สาขาอื่นไม่ทราบ — ยังค้าง |
| **ค่าน้ำ/ค่าไฟ ผ่านผู้ให้เช่า** | ✅ **ไม่ต้องหัก WHT** (ปิดธงแดง) |

| ⭐ **VAT 7% + WHT พร้อมกัน** | ✅ **หักจากฐานก่อน → ค่อยบวก VAT** (สูตรคำนวณ) |
| **50 ทวิ e-signature** | ⚠️ KMD: "ขึ้นกับกรมสรรพากร" แต่ **แนะนำเซ็นสด + ประทับตราจริง** |
| **e-WHT** | ⏸️ ยังไม่ได้ถาม Shibasan ว่าจะเปลี่ยนไหม + KMD outsource คุยช้า |
| **SaaS ตปท. (Zoom/Figma)** | ⚠️ "ไม่ต้องหัก เพราะบิลมาแล้วชิบะซังจ่ายไปเลย" ← **ดู RISK ล่าง** |

## 🚩 RISK ที่ต้องถาม KMD ใหม่ให้ชัด
> คำตอบ **"SaaS ตปท. ไม่ต้องหัก เพราะชิบะซังจ่ายไปเลย"** — นี่**ไม่ใช่คำวินิจฉัยภาษี**
> มันคือ *คำอธิบายว่าปัจจุบันทำยังไง* ไม่ใช่ *ทำไมถึงไม่มีหน้าที่หัก*
> ⚠️ **บริษัทจด VAT แล้ว** → ค่าบริการจากผู้ให้บริการต่างชาติ **อาจเข้าข่าย ภ.พ.36**
>   (VAT นำส่งแทน) และอาจเข้า ภ.ง.ด.54 ด้วย — ต้องถาม KMD ให้ตอบเป็นข้อกฎหมาย
> ⇒ **ถามใหม่:** "บริษัทมีหน้าที่ยื่น ภ.พ.36 / ภ.ง.ด.54 สำหรับ Zoom/Figma/Gather หรือไม่ เพราะเหตุใด"

## ⛔ จุดที่ห้ามเดา — ต้องถาม KMD ก่อน build

- การหัก **ค่าภาษีที่ดินและสิ่งปลูกสร้าง 5%** — หักยังไง คิดจากอะไร
- **ค่าบริการอุปกรณ์** ที่แตกออกมาต่างหาก — เป็นหมวดแยกจริงไหม
- บิลค่าเช่าที่มี **VAT 7% + WHT** พร้อมกัน — ลำดับคำนวณ (หักจากฐานก่อน/หลัง VAT)
- ค่าน้ำ/ไฟที่จ่ายผู้ให้เช่า vs จ่ายการไฟฟ้าตรง — อันไหนหัก อันไหนไม่หัก
- ทำไมบางเจ้า "แต่งตั้งให้นำส่งเอง" ได้ แต่บางเจ้าไม่ → ขยายให้ครบได้ไหม

## AS-IS Flow (จาก WHT diagram · 14 Jul)
```
Vendor ส่งอีเมล (แนบ Invoice) → Admin download PDF
  ├─ print Invoice → scan → Invoice + สำเนา
  └─ Calculate Tax (ตามประเภทค่าใช้จ่าย) → Create Transaction
       → Shibasan Approval → ได้ Payment Date
  → สร้าง WHT Tax Document (50 ทวิ) → scan → ต้นฉบับ + สำเนา (KMD/Liclass/Vendor)
  → สร้าง Pay Voucher (ยอดหลังหัก) → scan → ต้นฉบับ + สำเนา
  → Pay Slip → scan → ต้นฉบับ + สำเนา → ส่งรูปกลับ Vendor
  → แยก 3 ปลายทาง: Save to PC (ดิจิทัล) · KMD (ต้นฉบับ) · Vendor (50 ทวิ + slip)
```
**Root pain:** เอกสาร 1 ชุด × print × scan × copy × แจก 3 ที่ = โรงงานกระดาษ

**⭐ Shibasan มี 2 บทบาทแยกกัน (จาก diagram v2):**
1. **Approval** → อนุมัติ transaction → ได้ Payment Date
2. **Sign a signature** → **เซ็นทั้ง WHT Tax Document (50 ทวิ) + Pay Voucher** ทุกใบ
   - = คอขวดตัวจริง (32 ใบ/เดือน × 2 ประเภทเอกสาร)
   - โยง E2.5 "เซ็นใบเปล่าล่วงหน้า" = ทางลัดอันตรายเพราะการเซ็นเป็นคอขวด
   - 🎯 **Digital signature** (ระบบมี pattern แล้ว) เซ็นหลัง validate = ปลอดภัยกว่าใบเปล่า
   - ⚠️ รอ KMD ยืนยัน e-sign บน 50 ทวิ (กค 0702/1057) — คำถามข้อ 5

**Automation targets:**
- 🥇 **e-WHT** → ธนาคารหัก+นำส่ง → **WHT Tax Document หายทั้งกล่อง**
- 🥈 **Document-native** (generate PDF + vault + แชร์ดิจิทัล) → print/scan/copy หายเกือบหมด
- manual ที่เหลือจริง: Calculate (deterministic ถ้ามี Vendor master) · Shibasan approve (by exception)
- Payment Date มาจาก Shibasan approval · Pay Slip = หลักฐานส่งกลับ vendor
